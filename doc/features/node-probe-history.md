# 节点探测历史与订阅汇总

## 线上诊断（2026-11-18，只读）

检查 `192.168.9.253:/etc/sing-box/sing-box-easy.db` 时：

- 只有 `subscription_probe_samples`，没有逐节点历史表。
- Kitty Network（`sub_004712bffeff051e53198640d8f5b80b`）有 943 条汇总；每轮包含 28 个节点。
- 韩国节点完整 tag 为 `🇰🇷Korea 01 3b7d7f86 | sub_004712bffeff051e53198640d8f5b80b`。
- sing-box 的该节点 `history` 只有一条：`2026-11-18T08:46:59Z`，254ms。

原实现将订阅探测的逐节点结果汇总入库，只在内存保留最新一轮节点结果。代理页直接使用 sing-box 的缓存，故手动测速替换缓存后仍然只有一个采样。过去的平均值不能恢复成各节点历史，本次不伪造或回填旧数据。

## 统计口径

| 测速入口 | 节点历史 | 订阅汇总历史 |
| --- | --- | --- |
| 订阅定时整轮探测 | 每个实际测量的节点追加 | 本轮完成后追加一条 |
| 订阅质量面板“立即探测” | 同上 | 同上 |
| 代理页节点测速 | 追加该节点记录 | 不追加 |
| 代理页分组／全部测速 | 追加被测节点记录 | 不追加 |

随意选择的代理分组并不等于完整订阅；高频点击单个节点也不应改变订阅历史的抽样权重。节点历史保留 `source` 和 `test_url`，以便区分测量入口与测试目标。没有响应的实际 URL 测试记为失败；节点不存在、取消前未执行的任务、控制接口故障不当作节点失败。

本功能记录的是面板调用的测试。sing-box 内部独立 URLTest 产生且未经过面板的测试不保证逐次归档；代理页刷新也不会把相同缓存重复当成新采样。

## 存储和读取

- `node_probe_targets`：完整节点 tag、订阅归属和测试 URL；避免在每条采样里重复长文本。
- `node_probe_samples`：目标 ID、毫秒时间、延迟、明确成功状态和测速来源。成功的 0ms 与超时分开保存。
- `node_probe_membership`：订阅当前拥有的节点 tag 集合，作为清理后的写入屏障。
- 年龄和每实体采样上限复用探测保留设置（默认 7 天、每订阅／节点 2016 条）；写入时清理，修改保留设置也立即清理。
- `/runtime/proxies` 每节点只附最近 100 条（覆盖质量标准允许的最大窗口）；图表打开时通过 `/runtime/proxies/history?name=…` 查询该节点完整保留历史，避免每五秒重发所有图表数据。
- 设置页同时展示订阅汇总和节点采样数量及估计占用。

## 节点移除

订阅更新应用配置后按完整当前节点集清理：被移除节点的历史删除，未改变节点保留。重试即使得到空 diff，也按当前配置再次协调。删除订阅则清空该订阅所有节点历史。历史订阅汇总仍表示当时那一轮真实测量，不按当前节点集合改写过去。

变更前排空订阅探测；节点清理和归属集更新在同一 SQLite 事务里进行。移除前已经发出的手动请求即使迟到，也会被归属集拒绝，不能重建已删除数据。节点重新加入时允许重新积累，但不会恢复旧记录。

## 验证

覆盖重复自动／手动／分组测速、重开数据库、超时和 0ms 成功、单次写入原子性、按节点隔离、保留策略、订阅更新和删除、迟到结果、控制接口故障；验证手动节点与任意分组测速不增加订阅汇总。
