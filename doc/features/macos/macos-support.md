## 1. 目标与当前基础

首版提供一个可以双击启动的 macOS 应用，复用现有 Vue 管理界面和 Go 业务逻辑，随应用提供 sing-box。用户无需安装 Go、Bun 或 Homebrew，即可管理订阅、编辑配置、启动 HTTP/SOCKS 代理和查看日志。

首版默认面向 Apple Silicon、macOS 13 及以上。应用使用普通用户权限，不接管系统代理、DNS 或路由；关闭应用后停止其管理的代理进程。Intel、菜单栏常驻、系统代理、TUN 和公开分发分阶段处理。

### 1.1 已验证事实

- 后端 `GOOS=darwin GOARCH=arm64 CGO_ENABLED=0 go build ./main.go` 已通过，验证产物输出到临时目录。这只证明后端可以编译，不代表桌面、网络或代理功能已验证。
- `app/webui` 已支持嵌入前端静态资源，现有发布流程先构建 Vue，再嵌入 Go 二进制。
- `app/pkg/singbox` 已抽象服务后端，具有直接启动子进程的实现。
- `.github/workflows/release.yml` 当前发布 Linux 压缩包和 OpenWrt IPK，没有 macOS `.app` 或 DMG。
- 现有初始化路径以 `/etc/sing-box` 为主，内核安装流程面向 Linux/OpenWrt。
- 现有部分服务状态和停止操作按进程名查找 sing-box，不能直接用于需要隔离其他代理客户端的桌面模式。
- `app.Run` 绑定 `:<port>`，生命周期中尚未统一回收桌面拥有的内核。路由启动也需要补充可观察的就绪、错误返回和关闭接口。
- 前端主要使用相对 API 地址，并有部署状态、初始化默认值和流式数据读取能力，可以按部署模式适配。

### 1.2 首版边界

| 能力 | 首版决定 |
| --- | --- |
| 原生窗口、本地配置与订阅管理 | 支持 |
| 内置 sing-box、HTTP/SOCKS 代理 | 支持 |
| 日志、流量和现有诊断页面 | 支持适用于普通代理的能力 |
| 管理其他客户端或 Homebrew 的内核 | 不支持 |
| 独立安装、切换或升级内核 | 不支持，随应用更新 |
| 系统代理、TUN、管理员授权 | 后续阶段 |
| 菜单栏常驻、开机启动 | 后续阶段 |
| 远程服务器管理模式 | 不在本次范围 |
| 自动更新整包、Mac App Store | 不在首版范围 |

## 2. 架构选择

采用 **Wails v2 桌面外壳 + 现有 Go 后端子进程 + sing-box 子进程**。

桌面框架锁定 Wails `v2.15.0`，继续使用现有 Vue 3、Vite 7 和 Bun。保留现有 HTTP API 和业务服务，不把所有接口重写为 Wails bindings。

```text
Wails 桌面进程
  ├─ Vue 页面：应用内嵌静态资源
  ├─ /api/*：原生中间件代理并注入会话凭证
  └─ Go 后端子进程：127.0.0.1 随机端口
       ├─ SQLite、配置、订阅、诊断和后台任务
       └─ 应用专属 sing-box 子进程
```

Wails 负责窗口、原生菜单、单实例和退出事件。独立后端负责业务与内核所有权，避免将 Hertz 的阻塞启动和信号处理嵌入窗口主线程。桌面入口与服务器入口分开，通过构建标签或隔离的桌面模块使 Linux/OpenWrt 构建不依赖 macOS SDK。

### 2.1 前端与后端通信

- Vue 页面从应用包内加载，继续使用相对 API 地址。
- Wails AssetServer 的原生中间件截获 `/api/*`，代理到本次启动的固定后端地址；其他请求交给静态资源处理。
- 中间件保留方法、正文、状态码和流式刷新，客户端取消必须传播到后端。不能把日志和流量流完整缓冲后才返回。
- SPA 的前端路由刷新仍返回入口页面；不存在的 API 不能回退成 HTML。
- 原生代理不接受前端指定目标主机或端口，不成为任意地址代理。
- 窗口只加载受信任的应用页面，外部 HTTP/HTTPS 链接交给系统浏览器；禁止远程页面获得桌面 bindings。

Wails 官方文档列出了 macOS 响应流支持，也提示 Wails v2 自定义 AssetHandler 与新版 Vite 开发服务器存在限制。因此首版桌面调试使用构建后的内嵌静态资源；普通页面开发继续使用现有 Vite 流程，不降级 Vite。[Wails Options](https://wails.io/docs/reference/options/)

### 2.2 本地认证

桌面模式不要求用户创建账号或登录，但不能将其等同于一个无需认证的本地 HTTP 服务。

1. 桌面进程每次启动生成 256 位随机会话密钥。
2. 使用继承的匿名管道将密钥和运行参数传给后端，不使用命令行、URL 或持久化配置传递密钥。
3. 原生 API 代理注入专用认证头，并覆盖请求中已有的同名头。
4. 后端在进入业务路由前校验凭证，包括桌面模式下的部署状态和初始化接口。
5. 密钥只保存在原生进程内存，不写日志或 localStorage；后端退出即失效。

后端仅绑定 `127.0.0.1`，不开放 CORS。随机端口只是避免端口冲突，不能替代凭证。现有服务器模式继续使用原有账号鉴权策略。

## 3. 启动、运行和退出

### 3.1 启动顺序

1. 获取单实例锁；第二次打开仅激活已有窗口。
2. 创建用户数据和日志目录，检查内置内核是否存在及架构是否匹配。
3. 创建桌面到后端的控制管道及后端到桌面的就绪管道，启动后端子进程；控制描述符不能继续继承给内核。
4. 后端校验参数，初始化数据库和业务模块，绑定 `127.0.0.1:0`。
5. 路由可服务后，通过就绪管道返回实际地址和启动结果；普通日志使用独立输出，不与控制消息混合。
6. 桌面安装 API 代理后进入初始化向导或 Dashboard。
7. 首版不自动启动代理，由用户点击启动。

启动超时为 15 秒。失败时展示可复制的错误、打开日志和重试入口。重试之前清理失败实例，不同时运行两套后端。

生命周期状态区分：`starting`、`ready`、`failed`、`stopping`、`stopped`。内核另行显示停止、启动中、运行中、停止中和失败状态，不能用窗口存在来推断代理可用。

### 3.2 内核进程所有权

桌面增加专属服务后端，沿用服务控制接口，但只操作自己创建的进程句柄。禁止使用 `pgrep sing-box`、`pidof` 或按名称终止进程。

- 启动前执行内置内核的 `check`，校验成功后再启动实际运行进程。
- 服务状态来自子进程退出事件和实际句柄；启动时间由管理器记录，避免依赖 Linux `/proc`。
- 端口冲突、校验失败和启动后提前退出必须返回失败原因，不仅凭“等待两秒没有 FATAL 日志”宣布成功。
- 启动、停止、重启串行化；重复停止幂等。
- 停止先向所属进程发送 SIGTERM，等待 5 秒；仍未退出才发送 SIGKILL，随后等待进程回收。
- 内核自行退出时更新状态并显示原因；首版不无限自动重启。

### 3.3 退出和崩溃恢复

关闭窗口与 `⌘Q` 均退出应用。首版不隐藏窗口后继续后台代理。

正常关闭顺序：禁止新操作，取消流式请求和后台任务，停止所属内核，关闭 HTTP 服务和数据库，退出后端，释放桌面单实例锁。关闭方法需要幂等，错误应写日志并展示必要的退出失败信息。

后端持续监视桌面控制管道。桌面崩溃时管道 EOF 触发同样的清理，不依赖前端 JS 执行退出请求。

强制杀死后端可能遗留内核，不能保证所有异常都完成清理。保存进程身份记录，包含 PID、启动身份、可执行路径和配置路径。下次启动时，只有这些信息与实际进程完全匹配，才清理旧实例；身份无法确认时显示冲突，不终止未知进程。陈旧 PID 记录不能单独作为杀进程依据。

## 4. 应用包、数据与内核

### 4.1 目录布局

应用包内包含桌面可执行文件、后端、同架构的 sing-box、图标、版本清单和第三方许可材料。运行时不修改应用包内的文件。

```text
~/Library/Application Support/sing-box-easy/
  config.json
  sing-box-easy.db
  cache.db
  rulesets/
  runtime/

~/Library/Logs/sing-box-easy/
  app.log
  backend.log
  sing-box.log
```

数据目录默认 `0700`，配置和数据库默认 `0600`。SQLite 附属文件也应受相同用户权限保护。日志设置轮转上限，错误信息不得泄露订阅凭证、代理密码或会话密钥。

内核工作目录固定为应用数据目录，不依赖 Finder 的启动目录。新生成配置采用解析后的绝对路径。导入配置保留原始内容，但必须检查外部文件引用是否可访问；不能默默将其他应用路径映射到本应用。

### 4.2 内核版本和数据兼容

- 首版固定内核 `1.12.12`，与当前 Go 依赖基线一致；这是一项首版设计默认值，不宣称它是最新版本。
- 打包记录内核版本、架构及 SHA-256，构建阶段执行版本检查。
- 不依赖用户 PATH，不发现或接管 Homebrew、`/etc/sing-box` 和其他客户端的配置。
- 保留现有配置导入能力，不自动迁移历史服务器数据库。
- 应用更新可替换内核；首版不开放内核安装、切换或独立升级。
- 沿用已有配置保存、校验与回滚机制，不把应用打包变成另一套配置存储实现。

## 5. 公共接口与页面适配

### 5.1 最小接口变化

保留已有 API 前缀和响应 envelope，不进行全面 API 重构。新增桌面运行参数与生命周期入口，使服务可以返回真实监听地址、报告启动失败，并接受显式关闭。

现有部署状态响应增加可选信息：

- `deployment_mode`：`server` 或 `desktop`。
- 系统类型补充 `darwin`。
- 运行能力：内核安装、应用原地更新、TUN、系统代理、后台驻留是否可用。
- 桌面初始化所需的解析后默认路径。

操作能力以部署模式及后端策略为准，不能仅凭 `darwin` 推断“桌面应用”。旧客户端忽略新增字段；新前端连接旧服务器时保留现有默认行为。

桌面专用能力限制同时落实到后端。隐藏按钮不能作为拒绝内核安装、覆盖应用二进制或启动 TUN 的唯一保障。

### 5.2 页面行为

| 页面或能力 | 桌面首版行为 |
| --- | --- |
| 初始化向导 | 展示内置内核版本，跳过下载安装步骤 |
| 入站配置 | 默认选择 mixed，监听 `127.0.0.1:7890` |
| TUN、透明代理 | 显示首版不支持，后端启动校验不能被原始 JSON 绕过 |
| Clash API | 默认 loopback，生成独立随机 secret，用于现有诊断 |
| 外部 Dashboard | 隐藏下载步骤，使用项目自身界面 |
| 登录、用户、个人资料 | 桌面模式隐藏 |
| 配置、订阅、节点规则、DNS、路由 | 复用现有页面，按内核与桌面能力限制操作 |
| 日志、流量 | 保留流式展示，页面离开后取消请求 |
| 关于与更新 | 分别展示应用和内核版本，提供应用下载页面入口 |

端口冲突时保持停止状态，指出冲突端口并允许修改，不自动换端口。HTTP/SOCKS 默认只监听 loopback。首版拒绝需要特权的入站及自动修改系统代理的配置；该限制同时覆盖导入、原始编辑、历史回滚后的启动。

默认窗口 `1280×820`，最小 `960×640`。保留系统标题栏、复制、粘贴、全选及退出菜单。重点验证 Monaco、中文输入、暗色模式、文件导入导出；涉及浏览器下载的现有代码需在真实 WKWebView 中验收。

## 6. 构建、更新和分发

### 6.1 个人试用构建

增加独立 macOS 手动构建流程，默认只上传 CI artifact，不改变现有标签发布行为。

构建顺序：

1. Bun 使用锁文件安装依赖，执行 `bun run build`。
2. 在 macOS runner 上构建桌面和后端，桌面使用 macOS SDK 及所需 CGO 配置。
3. 获取固定版本和固定校验值的 sing-box，验证版本及架构；不使用动态 `latest`。
4. 组装 `.app`，写入版本、图标和稳定 bundle identifier。
5. 从内向外对嵌套可执行文件及应用进行 ad hoc 签名。
6. 生成 `sing-box-easy-macos-arm64.dmg`、SHA-256 和构建版本清单，上传 artifact。

前端和后端使用同一应用版本标记，内核版本独立记录。校验值固定在受版本控制的构建配置中。随包提供实际使用依赖的许可材料和所需源码获取信息。

个人试用包不宣称经过 Apple 公证，说明其本机构建和下载试用的区别；不将关闭系统 Gatekeeper 作为安装步骤。

### 6.2 首版更新策略

用户下载新包，退出后替换整个 `.app`。用户数据目录保留，首版不引入自动更新框架。

桌面后端明确拒绝现有“覆盖运行中二进制并 exec”的更新操作，避免修改应用包及破坏后续签名。应用升级前保存数据库备份；若数据库迁移已经发生，回退应使用对应备份，不宣称旧程序可以读取任意新数据库。

### 6.3 正式公开发布

个人试用验收后再增加 Developer ID、Hardened Runtime、公证和 staple。正式任务缺少证书或公证失败时应失败，不得静默降级为个人试用包。[Apple Developer ID](https://developer.apple.com/developer-id/)

通过正式发布门槛后，将 macOS 任务接入现有 Release 的共享 tag 与前端构建流程，保留 Linux tarball 和 OpenWrt IPK 的名称、结构和上传逻辑。Intel 使用独立构建与实机验收，不能仅凭交叉编译宣布支持。

## 7. 后续阶段

### 7.1 菜单栏和系统代理

下一阶段增加显示窗口、启动/停止、系统代理和退出菜单。届时关闭窗口改为隐藏，明确退出才停止后台服务；升级时需要清楚告知行为变化。

系统代理只在内核就绪后开启。按网络服务保存原始设置及本应用写入值；关闭时只有当前值仍匹配本应用写入值才恢复，避免覆盖用户或其他客户端的后续操作。必须覆盖 Wi-Fi/网卡切换、内核崩溃、应用退出和下次启动恢复。

设置 HTTP/SOCKS 系统代理不等同于 TUN；界面要说明只影响遵循系统代理设置的应用。此阶段不顺带修改系统 DNS。

### 7.2 TUN

TUN 作为独立评审和实施里程碑，以原生 NetworkExtension 为评估方向，不通过整个 GUI 提权实现。需单独确定扩展与内核集成、授权、网络生命周期、DNS 恢复、断网和休眠恢复。

当前 CLI 子进程不能直接等同于 NetworkExtension 集成。sing-box 官方 Apple 客户端使用 NetworkExtension 提供非特权 TUN；具体集成仍需验证，不能把“官方支持”写成“本项目已支持”。[sing-box Apple 特性](https://sing-box.sagernet.org/zh/clients/apple/features/)

## 8. 验证与实施顺序

### 8.1 自动检查

- 后端改动执行 `go test ./...`，增加桌面生命周期、进程所有权、会话认证和能力限制的针对性测试。
- 使用可控测试子进程覆盖启动失败、提前退出、优雅停止、超时终止和控制管道 EOF，不依赖真实外部代理服务。
- 验证错误 PID、PID 复用和不匹配路径不会触发终止；后台任务与流式请求在退出后释放。
- 验证无凭证的 loopback 请求失败，安装和应用原地更新不能绕过桌面策略。
- 前端执行 `bun run build`，验证既有 Linux/OpenWrt 构建仍通过。

### 8.2 macOS 实机验收

| 场景 | 通过标准 |
| --- | --- |
| 干净用户、无 Homebrew、无全局 sing-box | 双击启动并完成初始化 |
| 中文、空格路径和只读应用包 | 配置、缓存和日志均写入用户目录 |
| 重复打开、启动失败后重试 | 只有一个有效桌面实例和后端 |
| 订阅导入、配置保存和回滚 | 业务逻辑正常，内核校验结果准确 |
| 实际 HTTP/SOCKS 请求 | 请求经过所选出站，而非只验证端口监听 |
| 其他客户端占用端口 | 明确报错，不误识别或停止其他进程 |
| 正常退出、桌面崩溃 | 所属内核停止，数据库和任务被回收 |
| 后端被强杀、残留身份记录 | 下次启动只处理身份匹配的旧实例 |
| 内核校验失败、运行中退出 | 显示失败原因，不显示虚假运行状态 |
| 日志和流量持续输出 | 无完整缓冲，离开页面后释放连接 |
| 原始配置包含 TUN 或系统代理修改 | 后端拒绝启动，并指出不支持项 |
| Monaco、中文输入、文件导入导出 | WKWebView 中完成实际交互 |
| 替换应用与数据库备份恢复 | 数据保留，回退边界清晰 |
| 原有服务器部署 | 鉴权、服务控制和发布产物保持兼容 |
